# `osgi-itest/src/test/resources/etc` — Karaf `etc/` overrides swapped into the Pax Exam container before boot

| File | Purpose |
|---|---|
| `org.ops4j.pax.logging.cfg` | Sets the log4j2 configuration the integration container boots with, replacing Karaf's stock file via `replaceConfigurationFile("etc/org.ops4j.pax.logging.cfg", ...)` in `KarafFeatureProvider.karafConfig`. Defines `log4j2.pattern`, root level `DEBUG`, appenders `Console` (threshold `${karaf.log.console:-INFO}`), `RollingFile` (`${karaf.log}/karaf.log`, 16MB `SizeBasedTriggeringPolicy`) and `PaxOsgi` (filter `*`). Root level `DEBUG` means `BufferedSlf4jLogger` output in the ITests reaches `karaf.log`; lowering it hides validation diagnostics. Last line is a stray `s` — inert to the properties parser, do not treat as a key. |
| `org.ops4j.pax.url.mvn.cfg` | Points pax-url-aether at the developer's own Maven setup, and is copied into the container ONLY when the build runs with `-DuseCustomSettings=true`. Sets `org.ops4j.pax.url.mvn.settings=${basedir}/../.maven.xml`, `certificateCheck=true`, `useFallbackRepositories=false`, three `defaultRepositories` (system/kar/child, all `@snapshots`), remote `repositories` central + Apache snapshots + ops4j sonatype snapshots, plus `timeout=5000` and socket/connection tuning (`readTimeout=30000`, `retryCount=3`). `localRepository` is deliberately unset, so the container falls back to the ambient local repo; a missing `../.maven.xml` makes every `mvn:` bundle resolution fail at container start. |
